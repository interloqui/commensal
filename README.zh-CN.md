# 同桌（commensal）— 一个 LLM 原生项目的工程实践投影

> 同桌（commensal）是一个长期演进的 LLM 原生软件项目。本仓库不是它的镜像，而是它的对外投影：从项目私有的工作记录中，选择性公开我们认为对更广泛的 LLM 工程社区有独立价值的实践、机制设计与经验教训，并重写为阅读友好的文本。

本 README 另有[英文版](README.md)与 [gene-compact 版](GENE.md)——面向 LLM 的紧凑文档格式（见[内容规划](#内容规划)）。

## 为什么有这个仓库

项目本体在一个私有仓库中演进，积累了一些非常规的工程实践：如何在二十余条跨越数周的任务链上组织 LLM 的长程工作；如何让规格文档随裁定累积而保持亚线性增长；如何在 LLM 之外用 fail-closed 的机械门治理其输出。这些实践的价值不依赖于项目研究目标成立与否——但它们此前只存在于为 LLM（而非人类）优化的内部紧凑格式文档里。

本仓库存在的理由：把这部分有独立价值的工程经验，重写为阅读友好的公开文本。

不直接公开主仓库，原因有二：其一，项目的研究本体尚未定稿，过早全文公开会损害后续验证——其中包含需要外部参与者「未受污染」的盲测；其二，内部文档为紧凑格式，直接公开对读者不友好——公开意味着重写，重写意味着选择。

## 预期运行方式（目标态）

- **投影，非镜像**：所有内容从私有主仓（事实源）经「白名单选择 + 阅读友好重渲染」生成。本仓库可弃、可从源重建，提交历史不构成承诺。
- **发布管线（半自动）**：机械收集自上次发布的差分 → LLM 渲染（去内部化、改写为阅读友好）→ 机械检查（密钥/内部标识扫描，fail-closed——未通过者不出）→ 人工终审 → 推送。
- **节奏锚定语义完成点**：发布跟随内部工作单元的闭合，而非固定日历周期。
- **不镜像内部 git 历史**：每次发布是内容快照。

## 内容规划

- **链系统（task-chain）**——把任务链作为长期演进的 LLM 原生软件项目的工程基础；其在本仓库维护回路中的角色，大致可视为机械判定与语义判定合取的迭代门。本仓库仅展示链系统的固定版本快照，仓库内容的维护亦将由所展示的版本承担。
- **文档信息处理机制**——把项目正在使用的记忆/整理/遗忘机制反身应用于规格文档自身：三面结构（母本 → 分区打印 → 投影），使文档增长保持亚线性。
- **gene-compact**——面向 LLM 读者的紧凑文档格式。本仓库的 [GENE.md](GENE.md) 即活体样本。
- **fail-closed 门组**——在 LLM 之外机械治理其输出的门设计：欠定、对称律、出处解析。
- **经验帖**——从项目摩擦记录改写（并脱敏）的工程教训。
- *（后续）*研究本体的介绍——待验证推进到合适阶段。
