# 任务链——长期演进的 LLM 原生项目的工程基础

> 本文来自本仓库背后的项目：我们如何用**任务链**组织 LLM 的长程工作。它是内部工程文档的选择性投影——重写而非镜像。在本仓库的维护回路中，链系统的角色大致可视为机械判定与语义判定合取的迭代门；本仓库仅展示链系统的固定版本快照，仓库内容的维护亦由所展示的版本承担。

## 1. 问题：会话会结束，工作不能

LLM 会话有一条**单会话质量边界**：上下文窗口、注意力预算、token 配额。任何大于这条边界的工作单元，硬塞进一个会话里都会劣化——所以长程工作必须跨会话分解。

但没有结构的分解会腐烂：后一个会话在未经验证的前序产出上施工；意图在一次次交接中漂移；几周之后没人能回答*这个文件是哪一步改的、为什么*。任务链的存在就是让分解本身成为工程工件：

- **每一步在被继续建设之前先被检查**；
- **每一处变更可归因**到某条链的某个任务；
- **每一次交接写下具体可验证的预期**，供继任者核对。

链不是工作流引擎，也不是给人的任务队列。它是一个纯文件目录——LLM 能读、能写、能被问责的最廉价基座，同时承载以上三条保证。

## 2. 任务模型

```
LLM_{n-1}  --handoff-->  LLM_n  --handoff-->  LLM_{n+1}
              <--inspect--        <--inspect--
```

链中任意一个 LLM 承担三项操作，缺一不可：

### 2.1 INSPECT——对前序的关卡

链上的信任不是继承的。第 *n* 步未捕获的错误，会原封不动地成为第 *n+1* 步的地基；而会话边界处恰恰没有人替你把关——前一个 LLM 已经不在了，能对话的只有它留下的文件。INSPECT 把「相信前序」换成「核对前序」：对照它 handoff 里写下的预期（预期产出＋已声明的开放风险）与工具预处理出的变更清单，逐条核对产出是否与声称相符、是否对项目无净伤害，给出 PASS / FAIL / WARN 与具体偏差描述。它必须先于 EXECUTE——未校验即施工，等于把检查的成本转嫁给未来某个错误更难定位的会话。发现 FAIL 时按偏差大小处置：小修、回退、或标记为已知风险后继续，处置本身留痕。

举一个例子。前一任务交付了输入去重模块，handoff 声称「静默窗内连续到达的行属同一交互意图」。继任者不直接在其上施工，而是重放三类输入——慢速逐行键入、整段粘贴、两段间隔恰好压在窗沿上——第三类暴露了把两次独立输入并成一次的缺陷。偏差入档，小修，继续。这道关卡在这里回本：同一个缺陷若漏到上层，会表现为「上游偶发丢事件」，定位成本高一个量级。

反过来的情形同样真实：如果继任任务只是给文档改三处错别字，前序地基与它几乎无关，完整走一遍 INSPECT 是纯开销。关卡密度应当与地基实际承重匹配——这个模型服务于「后一步真的建在前一步之上」的工作，而非一切工作。

### 2.2 EXECUTE——执行子任务并留下可溯源记录

EXECUTE 的主张只有一半是「把活干完」，另一半是「让活可归因」。一切变更必须可被工具捕获——不存在不可见的编辑；执行记录必须显式声明所属的链与任务，否则三个月后「这次改动属于哪一步、为什么」只能靠考古回答。可溯源不是给审计看的装饰：跨会话的工作里，记忆是最先失效的东西，结构是唯一活到最后的证人。

例如，实现一个「依赖声明校验」子任务——规格要求「依赖字段构成 DAG：存在拓扑序、无环」。执行顺序是先写失败测试（构造含环的声明面，断言校验器拒绝），再实现，再跑全量回归；执行记录写下链号、任务号、变更文件与测试证据。三个月后有人问「拓扑检查为什么拒绝自依赖」，答案在结构里，不在任何人的记忆里。

边界同样明确：探索性原型（spike）——答案未知、产出大概率被丢弃、没有谁要建在它上面——不值得维持归因簿记。先做完、得出结论、把结论本身作为产出记下，比假装它是链上的一块地基更诚实。

### 2.3 HANDOFF——写下继任者的检查契约

HANDOFF 是站在继任者的视角为自己收尾：描述完成了什么、变更里该核对什么、哪里已知地不完整。它的核心纪律是*预期必须具体可验证*——「协议解析正确」不合格，「边界值 0/127/128/16383/2097151/268435455/2147483647 编解码与参考规范逐位一致」合格。区别不在措辞，在可判定性：前者留给继任者一个无法操作的相信，后者留下一张可以直接执行的核对清单。开放风险同理必须显式——沉默不等于无风险，只是把风险转嫁给不知情者。

对照最能说明问题。坏 handoff：「优化了性能，应该没问题」——继任者的 INSPECT 无从下手，只能全量重查，链退化成日记。好 handoff：「写入路径从逐条 flush 改为批量提交；预期：大批量写入耗时降约一个数量级、单条写入尾延迟上升；核对点：崩溃恢复后无半写状态（测试 X 覆盖）；已知风险：极小批量场景退化，未标定」——继任者半小时完成一次真正意义上的检查。

而当任务是链的最后一块时，HANDOFF 面向的不再是继任者，而是链自身的闭合与归档：写清验收对照与未竟余项，让「闭合」是一个可核的声明，而不是一次消失。

## 3. 五前提——分解何时成立

链不是免费的；五前提全部成立时它才回本。违反任一条，链模型不适用——回退单任务模式。

1. **单会话质量边界**：任务*无法*在一个会话中以可接受质量完成。分解因此不是"可以"而是*必须*；强行单会话完成必然质量坍缩。检测：子任务复杂度超过会话上下文的约 80%，或预期 token 消耗超过单会话预算。
2. **可分解且副作用可知**：任务能拆为相互依赖的子任务，且拆分本身不引入新的未知——拆分点有明确理由，边界处的信息损失被显式记录而非日后才发现。
3. **完成等价性**：全部子任务通过标准的 AND＝父任务通过标准——无遗漏、无额外。若子任务全过而父目标未达，分解有缺口，且缺口必须能回溯到具体某条标准。
4. **依赖/并行可表达为链**：依赖字段构成 DAG——存在拓扑序、无环。依赖=顺序链（INSPECT 前序工作）；独立=并行链（仅在合并点互相 INSPECT）。
5. **子任务间相互影响已知且明确**：两个子任务修改同一文件/同一函数时，冲突可能性被显式声明，禁止并行，强制顺序化。

## 4. 执行原则

**分解的横向与纵向。** 横向：同层级拆为并行独立的子任务——锚点集合无交集，合并点处交叉检查互不冲突。纵向：按依赖拆为顺序子任务——后一步建立在前一步产出之上，每步 INSPECT 验证前序。混合：先横向拆出独立维度，再纵向拆每个维度的依赖链。当分解涉及面广、副作用难以评估时，唯一可靠的判据是集成测试——评审看不见的副作用，恰是端到端执行才能暴露的。

**INSPECT 是责任，且有边界。** 检查前序不是可选的礼貌——它使继任者自己的工作有意义。但 INSPECT 是关卡不是任务主体：当前序产出差到检查本身会变成主要工作时（开放风险超出可接受范围、过半通过条款不过、或只有接口桩），检查*升级*为 EXECUTE——修复/补全前序产出，并显式标记升级与原因。

**机械的归工具，语义的归 LLM。** 机械筛选——改了什么、哪些文件、哪些声明——归工具；LLM 基于预处理清单做语义判断：逻辑正确性、接口一致性、设计意图对齐。一个会话对应且只对应一个任务文件，三项操作全部记录在该文件内。手动 grep/glob 定位前序产出是反模式：工具给不出来的，说明流程错了。

**首任务的特殊 INSPECT。** 没有前序可查时，检查转向分解本身：拆分是否过粗（单会话质量边界）、首个任务是否选取了简单但需要仔细完成以保证质量的活。首任务是链的地基；对它的检查就是对链结构的检查。

**紧凑语义字段+机械字段归工具。** 面向人/LLM 的叙述用紧凑的 `{KEY:value}` 条目（可按键扫描、无散文税）；时间戳、状态、声明、匹配计数由工具写入。LLM 不手维护它可能维护错的簿记。

**迭代兼容与有序更迭。** 链格式本身在迭代，而迭代遵循规则而非情绪：单一 schema 版本为权威；旧链文件保持可读（读取侧兼容档案）；格式迁移是显式的、带 golden 测试的单向变换——结构性不存在静默改写；弃用非删除；承载链系统的新版本由链系统自身施工（承载者吃自己的狗粮）。

## 5. 对象模型——设计决策

链系统的对象模型是一组有意的取舍，每条作为一个决策连同理由记录在案：

| 方面 | 决策 | 理由 |
|---|---|---|
| 存储 | 磁盘纯文件：一条链一个目录 | 无需任何工具即可被 LLM 读取、可 git diff、可 grep；数据库在这里挣不回它的复杂度 |
| 工件三件套 | 每链：*manifest*（身份+生命周期声明）、常驻链的 *charter*（行进方向，哈希锚定）、*任务文件* | manifest 是链的单一事实源；charter 防止常驻职责漂移；任务文件是只追加的历史 |
| 一文件一会话 | 一个任务文件对应一个 LLM 会话；INSPECT/EXECUTE/HANDOFF 全记录在文件内 | 归因与连续性：文件就是该会话与链的契约 |
| 链种类 | `terminal`（建成即归档）与 `standing`（常驻职责；休眠≠失效） | 有的工作会完结；有的工作是周期性职责，在轮次之间沉睡 |
| 状态即声明 | `planned / executing / delivered / closed / retired` 是声明值而非推断值 | 状态转移是语义判断：连同证据*登记*，检测器事后标记不一致 |
| 两层判定 | 工具只执法*格式事实*（schema 合法性、枚举边界）；质量状态过*软门*——以记录在案的证据面为据 | 机械检查封闭于它能证明的；其余的显式声明留痕，可拒绝，或带理由越道 |
| 纪元 | 带 cause 重开一条链即开启新纪元；计数由机械维护 | 长命链累积轮次；纪元让历史可读 |
| 原位归档 | 归档是 manifest 里的声明——零文件移动；深度冻结到历史区是可选项 | 发现面按声明过滤；移动文件会打断链接与历史 |
| 可溯源性 | 改动=取代指针+退役指针；删除=退役（文件永不删）；闭链时内容哈希快照检测闭后修改 | 历史是证据；篡改（哪怕意外的）必须可检出，而非靠信任预防 |
| 阅读记号 | ASCII 记号：任务 `+` 已闭 / `o` 未闭；链 `[dormant]` / `[archived]` | 整条链的状态一屏等宽字符可读 |
| 工具化 | 单一工具拥有全部机械操作（声明/视图/清扫/检索）；LLM 不手动翻找工件 | 机械真相有单一写者；LLM 的角色保持语义 |

## 6. 命令面

链工具的现行命令面，十五条（更早的工作流族——`init`、`inspect`、`intent`、`handoff`、`test-init`、`split`、`merge` 及簿记命令——已原位退役：保持可读，不再处于活跃面）：

| 命令 | 面 |
|---|---|
| `new` | 立链：manifest 登记（身份、动力、种类） |
| `task` | 链内加任务文件（时间分期延续，非头分裂） |
| `start` / `close` / `retire` | 声明生命周期转移（软门+证据面；闭链时哈希快照） |
| `charter` | 查看/声明常驻链的章程修订（哈希锚定） |
| `archive` / `unarchive` | 原位可见性翻转；cause 必填 |
| `reopen` | 开启新纪元；cause 必填；已归档链自动解除归档 |
| `status` | 带 ASCII 记号的生命周期视图、状态过滤 |
| `sweep` | 一致性清扫——只建议，不执行 |
| `lookup` | 跨 manifest 与章程检索（含已归档与冻结） |
| `freeze` | 可选深度冻结入历史区 |
| `checklist` | 只读的 INSPECT 预处理：前序 handoff、软门预演、脚手架 |
| `migrate` | 显式的旧格式变换（留档；被冻结的族刻意不迁移） |

## 7. 版本纪律

链格式迭代过不止一次，而迭代本身遵循规则而非情绪：

- **旧工件保持可读。** 每个读取器处理它可能遇到的所有格式；任何东西不需要先转换才能打开。
- **弃用非删除。** 退役的命令与冻结的链留在盘上、有文档、可显式路径直达。
- **迁移若发生，必是显式的。** 单向、带 golden 测试、带出处记录的变换——结构性不存在静默改写。
- **本仓库展示固定快照。** 你在这里读到的是链系统的一个版本；本仓库自身内容的维护，同样由所展示的版本承担。

## 8. 活体样本

本文旁的 [`chain_schema.py`](chain_schema.py) 是所展示版本的 schema 模块，按项目的直拷规则公开（裁定锚注释剥离、行内内部标识清理、行为 docstring 保留）。它是系统两侧共读的中立模块——派生链视图的运行时，与校验写入的工具链——而且小到可以一口气读完：声明状态机、让篡改可检出的快照哈希、格式事实校验器，以及面向旧文件的兼容档案。

关于本项目内部记录所用的紧凑文档格式——本仓库的 [GENE.md](../../GENE.md) 即其活体样本——见根 [README](../../README.md)。
